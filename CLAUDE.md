# ХроноКвест — навигация по проекту

Этот документ — карта проекта. Читай его в начале каждой сессии, чтобы понимать, где что лежит и как с этим работать.

## Что это за проект

**ХроноКвест** — игровой веб-тренажёр для запоминания дат по истории (ЕГЭ), для школьников 10–11 классов.
Каждая дата привязана к яркой ассоциации-запоминалке (а позже — к персонажу-иллюстрации), чтобы дата запоминалась сама, без зубрёжки. Есть два режима: обучение и квиз для проверки знаний.

Подробности — в `.business/INDEX.md`.

## Ключевые принципы проекта

1. **Запоминание без зубрёжки.** Даты запоминаются через мнемотехники (созвучия, рифмы, визуальные образы, эмоциональные зацепки). Ассоциации остроумные и яркие, но не абсурдные — баланс лёгкости и уважения к серьёзности материала.
2. **Учёба через игру.** Очки, уровни, прогресс-бар, серии дней («стрики») и достижения — не скучно и формирует привычку заниматься.
3. **Ориентир на результат ЕГЭ.** Бесплатные 50–100 дат = «гарантия на 50 баллов»; полный доступ ведёт к 70+, 80+ и вплоть до 100. Сначала отрабатываем текстовые ассоциации, персонажей добавляем позже.

## Принципы игровой механики обучения

Учитывать при проектировании UX и логики компонентов тренажёра дат. **Главная ценность: обучение через удовольствие и эмоцию, а не зубрёжку.**

1. **Мгновенная позитивная обратная связь.** Верный ответ — яркая приятная реакция (с персонажем-котиком/щенком). Неверный — мягкий, без наказания, с подсказкой и возвратом к ассоциации.
2. **Короткие сессии.** Блоки по 5–7 карточек за подход, а не длинные марафоны — чувство завершённости и маленьких побед.
3. **Streak (серия дней подряд).** Визуальный индикатор регулярности, мотивирующий не прерывать серию.
4. **Интервальное повторение (spaced repetition).** Даты, которые путают, показываются чаще; хорошо запомненные — реже. Система адаптируется под ошибки конкретного пользователя.
5. **Лёгкая случайность.** Не строго линейный порядок карточек; иногда случайные/бонусные карточки для непредсказуемости и вовлечения.
6. **Визуальный прогресс как история.** Не счётчик «20/50», а открывающаяся по эпохам карта/путь в стилистике вселенной персонажей.
7. **Низкая цена ошибки.** Никаких таймеров, жизней и давящего стресса. Спокойный темп; ошибка — часть обучения, а не провал.

## Стек

HTML + CSS + JavaScript (ванильный, без фреймворков) — выбран как самый простой для старта и черновой версии. При росте проекта возможен переход на React/Next.js (решим позже).

## Папка `.business/`

Скрытая папка с бизнес-контекстом проекта. Здесь живёт информация **зачем** мы делаем проект.

## Папка `plans/`

Технические планы реализации. Здесь живёт информация **как** мы делаем проект. Один план = одна функция.

## Как работать с проектом

- Перед любой задачей — прочитай этот файл, затем нужные документы из `.business/` и `plans/`.
- Если меняется бизнес-логика — обнови `.business/INDEX.md` и нужные файлы.
- Если меняется технический план — обнови соответствующий план в `plans/`.
- Если появляется новая важная папка или документ — обнови этот `CLAUDE.md`.

## ВАЖНО: план для каждой новой функции

Любая функция, которую мы создаём в любом чате, всегда оформляется планом в папке `plans/`.

Правила:

1. Один план = одна функция. Если план уже есть — работаем с ним.
2. Имя файла: `YYYY-MM-DD-название-функции.md`.
3. План делится на фазы. У каждой фазы статус `[ ]` или `[x]`.
4. В конце плана — итоговый блок: реализован целиком или нет, что осталось.
5. Любой агент обязан актуализировать план после каждой сессии.

## ВАЖНО: завершение каждого чата

В конце каждой сессии записывай рефлексию в файл `.business/история/YYYY-MM-DD-краткое-название.md` (создавай папку при необходимости).

Формат:

1. Какая задача была поставлена.
2. Как я её решал.
3. Решил ли — да / нет / частично.
4. Эффективно ли решение, что можно было лучше.
5. Как было и как стало.
