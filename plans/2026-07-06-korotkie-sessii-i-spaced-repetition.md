# План: короткие сессии + интервальное повторение

## Что делаем
Реализуем два принципа из CLAUDE.md, которые пока заявлены, но не работают в коде:
1. **Короткие сессии** (#2): квиз/карточки прогоняли все 101 дату за раз. Делаем раунды по 7 карточек
   с экраном-итогом «раунд пройден» и кнопкой «Ещё раунд».
2. **Интервальное повторение** (#4): сейчас квиз просто тасует все даты поровну, статистика
   `hard/streak` на выбор карточек не влияет. Делаем настоящий отбор по методу Лейтнера — слабые и
   «просроченные» даты возвращаются часто, выученные — редко.

## Как (алгоритм Лейтнера, «часы» в раундах)
- Добавляем в прогресс счётчик `round` и в статистику даты — `seenRound` (в каком раунде показана).
- «Коробка» даты = серия верных подряд (`streak`), обрезанная: box 0..4.
- Интервалы по коробкам (в раундах): `[1, 2, 4, 8, 16]`. Дата «просрочена» (пора показать), если
  `round - seenRound >= интервал(box)`. Никогда не виденная — всегда пора.
- `buildSession(7)` набирает раунд: приоритет — просроченные → сложные → низкий box (слабые) →
  давно не виденные, + лёгкая случайность (#5). Новых карточек за раунд не больше половины, чтобы
  повторение не тонуло в новом материале.
- Ошибка в квизе больше НЕ переспрашивается в том же раунде — карточка вернётся следующим раундом
  (её box сбросился в 0 → интервал 1). Это и есть интервальность.

## Область
- **Квиз** — раунды по 7 + отбор SR + экран-итог со счётом «X из 7». Пишет `seenRound`, растит `round`.
- **Карточки** — раунд по 7, отобранный тем же SR (фокус на слабых для активного вспоминания),
  БЕЗ записи в прогресс (как и было). Экран-итог без счёта.
- **Обучение** — остаётся линейным просмотром-справочником (богатая навигация: назад/далее/переход/
  список в прогрессе). Форсить раунды на режиме чтения — только вредить UX. Обновим лишь финальный экран.

## Фазы
### [x] Фаза 1. Данные прогресса
`round` в `defaultProgress`, нормализация при загрузке; `seenRound` пишется в `recordAnswer`.

### [x] Фаза 2. Движок SR
`SESSION_SIZE=7`, `SR_INTERVALS=[1,2,4,8,16]`, `boxOf`, `isDue`, `scoreCard`, `buildSession`.

### [x] Фаза 3. Квиз — раунды
`startQuiz`/`nextQuizCard`/`answer`/`finishQuizRound`; убраны переспрашивание и `solved`;
индикатор «Вопрос X из 7» (`#quiz-progress`).

### [x] Фаза 4. Карточки — раунды + общий экран-итог
`startFlip`/`flipNext` через `buildSession` (без записи в прогресс); `showDone(emoji,title,text,buttons)`;
`#screen-done` получил `#done-emoji` и контейнер кнопок `#done-actions`; финал обучения — тоже `showDone`.

### [x] Фаза 5. Проверка
`node --check` OK. Симуляция 40 раундов: путаемые даты 16–22 показа, выученные — в среднем 3;
все 101 введены. Первая формула давала «новым» перевес (wait=999) — переделал в `scoreCard`
(сложные/заваленные опережают ввод нового). Открыто в Chrome.

## Итог
Реализовано целиком. Квиз и «Режим карточек» теперь идут короткими раундами по 7 карточек с
экраном-итогом и кнопкой «Ещё раунд». Отбор карточек — по интервальному повторению (Лейтнер, «часы»
в раундах): слабые/сложные возвращаются часто, выученные — редко (проверено симуляцией). Обучение
осознанно оставлено линейным режимом-справочником. Связано: оценка проекта в
[[hronokvest-next-associations]].
