# План: Модальные окна — блокировка фона и вёрстка списка

## Цель
Починить поведение модальных окон (прежде всего «Перейти к дате») на мобильных и десктопе:
1. Пока модалка открыта — задний план (страница карточки) не должен скроллиться.
2. В списке дат первая колонка (дата) должна иметь фиксированную ширину, чтобы события всегда начинались на одной вертикальной линии.

## Фазы

- [x] Фаза 1. Блокировка прокрутки фона под модалкой (iOS-safe).
  - В `app/app.js` добавлены `lockBodyScroll()` / `unlockBodyScroll()` и обёртки `openModal(id)` / `closeModal(id)`.
  - Механика: при открытии запоминаем `window.scrollY`, фиксируем `body` через `position: fixed; top: -Y` (на iOS Safari одного `overflow: hidden` мало). При закрытии — снимаем стили и возвращаем страницу на прежнюю позицию через `window.scrollTo`.
  - Счётчик открытых модалок — фон разблокируется только когда закрылась последняя.
  - Подключено ко ВСЕМ модалкам: `jump-modal` (Перейти к дате) и `reset-modal` (сброс прогресса). Все пути открытия/закрытия (`openJump/closeJump`, `askReset/closeReset/confirmReset`) идут через обёртки.

- [x] Фаза 2. Фиксированная колонка даты в списке перехода.
  - В `app/styles.css` строка `.jump-item` переведена с `flex` на `grid` с `grid-template-columns: 116px minmax(0, 1fr)`.
  - Первая колонка (`.jump-date`) — ровно 116px, длинные диапазоны переносятся внутри столбца (`overflow-wrap: anywhere`), а не раздвигают разметку.
  - Вторая колонка (`.jump-event`) — `minmax(0, 1fr)` + `min-width: 0`, чтобы корректно работало усечение многоточием.

## Проверка
- Синтаксис `app.js` валиден (`node --check`), скобки `styles.css` сбалансированы.
- Открыто в Chrome для ручной проверки. Нюанс iOS Safari (position: fixed) требует финального теста на реальном iPhone.
